# 꽃가루 예보와 식물 지도 정보 분리 설계

- 작성일: 2026-09-26
- 상태: 승인됨
- 승인된 시각안: 데스크톱 C형 대시보드 카드 + 모바일 C3 접이식 요약
- 관련 상위 계약: `DESIGN.md`
- 대체 범위: `2026-07-26-pollen-realtime-push-design.md`의 Phase 1 패널 배치·표시 규칙을 이 문서가 갱신한다. API 및 푸시 설계는 대체하지 않는다.

## 1. 문제

현재 앱은 두 종류의 서로 다른 데이터를 한 화면에서 다룬다.

- 지도: 지자체·공공기관이 등록한 식물 위치와 수종의 정적 스냅샷.
- 꽃가루 패널: 기상청 지역 단위 일일 위험지수와 Google 잔디 예보.

현재 `PollenPanel`은 지도 본문 안의 얇은 행으로 놓여 있고, 위치 좌표가 없으면 안내 문구만 표시한다. 이 구조는 꽃가루 정보가 부가적인 지도 데이터처럼 보이게 하며, 사용자가 이를 실시간 현장 측정으로 오해할 여지도 있다.

## 2. 목표와 비목표

목표:

1. 오늘의 지역 꽃가루 위험지수를 페이지 상단에서 항상 발견할 수 있게 한다.
2. 예보 위험지수와 식물 위치 데이터를 시각적·언어적으로 분리한다.
3. 데스크톱에서는 전체 꽃가루 상태를 한눈에 보여준다.
4. 모바일에서는 지도 높이를 보존하면서 가장 중요한 위험을 우선 표시한다.
5. 기존 API, 지도 로딩, 필터, 통계 동작을 유지한다.

비목표:

- 새로운 꽃가루 데이터 공급자 또는 실시간 측정 데이터 도입.
- `/api/pollen` 응답 모델 변경.
- 새로운 지역 선택기 또는 알림 기능 구현.
- 지도 마커·클러스터·필터 알고리즘 변경.

## 3. 승인된 화면 구조

`App`의 직계 레이아웃 순서를 다음처럼 바꾼다.

1. `AppHeader`
2. `PollenPanel` — 페이지 전체 폭의 고정 상단 정보 영역
3. `app-body`
   - `Sidebar` — 식물 데이터 필터·통계·문의
   - `main-content`
     - 식물 데이터 오류/로딩 상태
     - `Map`

앱 자체가 `100vh` flex column이고 내부 지도 영역만 남은 높이를 쓰므로 별도 `position: fixed`는 사용하지 않는다. `PollenPanel`을 `app-body` 밖으로 이동하면 문서 스크롤 없이 헤더 아래에 계속 노출되고, 지도와 사이드바가 그 아래 남은 공간을 공유한다.

## 4. 데스크톱: C형 대시보드 카드

768px 초과 화면에서는 패널을 항상 펼친다.

- 상단 메타 행:
  - 제목: `오늘의 꽃가루 위험지수`
  - 설명: `기상청 예보 · 실시간 측정 아님`
  - 잔디 출처: `잔디: Google`
  - `generatedForKstDate`가 있으면 `기준일 YYYY.MM.DD`
- 카드 행:
  - 현재 지역 카드
  - 참나무
  - 소나무
  - 잡초류
  - 잔디
- 위험 단계는 기존 `낮음·보통·높음·매우높음`과 기존 색상을 유지한다.
- `offseason`은 `비시즌`, `error`는 `정보 없음`으로 표시한다.

패널 높이는 콘텐츠에 맞추되 한 행을 원칙으로 한다. 텍스트 확대나 좁은 중간 폭에서 카드가 감기면 패널이 자연스럽게 늘어날 수 있다.

## 5. 모바일: C3 접이식 요약

768px 이하 화면에서는 기본적으로 접힌다. 사용자 선택은 세션 간 저장하지 않는다.

접힌 행:

- 좌측: 지역명.
- 중앙: `status === "ok"`인 항목 중 가장 높은 `level`의 `라벨 + 단계`.
- 우측: 펼치기 버튼.
- 동률이면 API 배열 순서인 참나무 → 소나무 → 잡초류 → 잔디를 따른다.

예외 요약 규칙:

1. 모든 카테고리가 `offseason`이면 `주요 꽃가루 비시즌`.
2. 정상 항목 없이 `error`가 하나라도 있으면 `일부 정보를 불러올 수 없음`.
3. 위치가 없으면 `지도에서 내 위치를 눌러 오늘의 꽃가루를 확인하세요`.
4. 요청 중이면 `오늘의 꽃가루 불러오는 중…`.
5. 요청 전체가 실패하면 `오늘의 꽃가루를 일시적으로 불러올 수 없습니다`.

펼친 상태:

- 2×2 카테고리 카드.
- 예보/비측정 고지, 출처, 기준일.
- 접기 버튼.

토글은 `<button>`을 사용하고 `aria-expanded`, `aria-controls`, 명시적 접근성 이름을 제공한다. 데스크톱에서는 토글을 숨기고 상세 영역을 항상 표시한다.

## 6. 식물 지도 구분

지도 좌상단에 다음 정보 표면을 둔다.

- 주 라벨: `식물 위치·수종 지도`
- 보조 라벨: `지자체 등록 데이터 스냅샷`

기존 알레르기 등급 범례는 식물별 참고정보로 유지한다. 상단 꽃가루 위험지수의 색상 카드가 지도 마커 범례처럼 보이지 않도록 두 영역 사이에 경계선과 별도 배경을 사용한다.

사이드바의 의미는 식물 데이터 전용으로 유지하며, 필터와 통계 계산에는 꽃가루 위험지수를 섞지 않는다.

## 7. 데이터 흐름과 오류 격리

기존 흐름을 유지한다.

`useGeolocation → App → PollenPanel → fetchPollen → /api/pollen`

- 패널 이동은 데이터 호출 시점이나 좌표 공유 방식을 바꾸지 않는다.
- 꽃가루 호출 실패는 패널 내부 상태로 끝나며 지도는 계속 렌더링한다.
- 식물 데이터 로드 실패는 기존 지도 오류 배너가 처리하고 꽃가루 패널은 가능한 경우 계속 표시한다.
- 응답에 없는 새 시각이나 발표 시각을 추정해 표시하지 않는다. `generatedForKstDate`와 `updatedAt`만 사용한다.

## 8. 컴포넌트 변경 경계

- `src/App.jsx`
  - `PollenPanel`을 `app-body` 위로 이동한다.
  - 지도 본문에는 식물 데이터 상태와 지도만 남긴다.
- `src/components/PollenPanel.jsx`
  - 모바일 접힘 상태와 요약 선택 함수를 추가한다.
  - 데스크톱 카드, 모바일 상세 카드가 같은 카테고리 모델을 공유한다.
  - 위치 없음·로딩·오류에서도 동일한 외곽 컨테이너를 유지한다.
- `src/components/PollenPanel.css`
  - C형 카드 그리드와 768px 모바일 disclosure 규칙을 정의한다.
- `src/components/Map.jsx` 또는 지도 외곽
  - 식물 데이터 라벨을 추가한다. 지도 SDK 내부 DOM이 아니라 React가 소유하는 오버레이를 우선한다.
- `src/App.css`
  - 상단 패널을 포함한 flex 높이와 지도 남은 높이를 보장한다.

새 의존성이나 API 변경은 없다.

## 9. 접근성

- 패널은 이름이 있는 `<section>` 또는 동등한 landmark로 제공한다.
- 상태 색상에는 항상 텍스트를 병기한다.
- disclosure 버튼은 키보드로 조작 가능하고 포커스가 명확해야 한다.
- 모바일 접힘 상태에서도 가장 높은 위험 정보가 스크린리더 읽기 순서에 포함된다.
- `비시즌`과 `정보 없음`을 같은 문구로 합치지 않는다.
- 모션 감소 설정에서는 펼침/접힘 전환을 즉시 적용해도 정보 손실이 없어야 한다.

## 10. 테스트와 수용 기준

테스트는 구현 전에 실패하는 회귀 테스트로 추가한다.

### 컴포넌트 테스트

- `App`에서 꽃가루 영역이 `app-body`보다 앞에 렌더링된다.
- 위치가 없어도 꽃가루 영역 자체는 존재한다.
- 정상 데이터에서 지역 + 네 카테고리를 렌더링한다.
- 모바일 요약 함수가 가장 높은 정상 위험을 선택하고 동률에서 API 순서를 보존한다.
- 전부 비시즌이면 `주요 꽃가루 비시즌`을 반환한다.
- 정상 항목 없이 오류가 섞이면 부분 실패 문구를 반환한다.
- 토글 버튼이 `aria-expanded`를 바꾸고 상세 영역을 제어한다.
- 실패 상태가 지도 컴포넌트 렌더링을 막지 않는다.

### 정적·빌드 검증

- `npm run lint`
- `npm test`
- `npm run build`

### 수동 반응형 확인

- 데스크톱: 지역 + 네 카드가 상단에서 즉시 보인다.
- 모바일: 기본 접힘, 가장 높은 위험 표시, 펼치면 2×2 카드.
- 패널 상태가 바뀌어도 지도가 사용할 수 없는 높이로 축소되지 않는다.
- 상단에 `예보 · 실시간 측정 아님`, 지도에 `식물 위치·수종 지도`가 동시에 보인다.

## 11. 완료 조건

- 승인된 C/C3 레이아웃이 데스크톱과 모바일에서 재현된다.
- 사용자가 꽃가루 예보와 식물 지도 데이터를 문구와 배치로 구분할 수 있다.
- 기존 지도·필터·통계·제보 기능과 `/api/pollen` 계약이 유지된다.
- 신규 테스트와 전체 lint/test/build가 통과한다.
